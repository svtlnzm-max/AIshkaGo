# tg-beauty-catalog — Telegram Mini App «Нейро.Студия»

Каталог ИИ-услуг (фото, дизайн, тексты, боты) в формате Telegram Mini App.
MVP: HTML + CSS + JS без фреймворков, вся логика — на клиенте, без бэкенда.

## Документы проекта

- [research.md](research.md) — маркетинговое/UX/техническое исследование ниши и ограничений Telegram Mini Apps
- [brief.md](brief.md) — пошаговый план экранов (карта экранов, элементы, переходы, что не входит в MVP)
- **tg-app/** — сама реализация Mini App (описана ниже)

## Точка входа

`tg-app/index.html` — открывать его (в реальном использовании — через ссылку на бота, добавленную в BotFather как Mini App).

## За что отвечает каждый файл

| Файл | Отвечает за |
|---|---|
| `tg-app/index.html` | Разметка-каркас: `#screen-container` (сюда рендерятся экраны), `#tabbar` (нижняя навигация), подключение `telegram-web-app.js` и всех скриптов. Больше здесь менять почти нечего. |
| `tg-app/css/style.css` | Все стили. Цвета заданы CSS-переменными `--tg-*`, которые на реальном устройстве перезаписываются темой Telegram из `telegram.js`. Акцент `--accent: #2AABEE` задан отдельно. |
| `tg-app/js/data.js` | **Единственное место, где нужно менять контент**: название бренда (`BRAND`), категории (`CATEGORIES`), услуги и цены (`SERVICES`), шаги статуса заказа (`STATUS_STEPS`), моковые заказы для демонстрации истории (`MOCK_ORDERS`). |
| `tg-app/js/telegram.js` | Обёртка над Telegram Web App SDK: тема, MainButton/BackButton, HapticFeedback, CloudStorage, диалоги. Здесь же — фолбэк-версии этих элементов для предпросмотра вне Telegram (см. «Важный нюанс» ниже). |
| `tg-app/js/router.js` | Навигация между экранами: стек, анимации (slide/fade), показ/скрытие таббара и кнопки «Назад». |
| `tg-app/js/screens.js` | Разметка и поведение каждого экрана (`SCREEN_HANDLERS`). Если нужно поменять текст, поля формы или порядок блоков на экране — правьте здесь. |
| `tg-app/js/app.js` | Точка входа: общее состояние `AppState` (заказы текущей сессии, черновик заявки), запуск Telegram SDK, обработка кликов по `data-action`. |

## Карта экранов и переходы

```
Приветствие (один раз) → Каталог
Каталог ⇄ Категория ⇄ Карточка услуги → Бриф/заявка → Оплата → Статус заказа
Статус заказа --(готово)--> Результат
Таббар: Каталог · Мои заказы · Профиль (Профиль → Поддержка / О сервисе)
```

Полное описание элементов и переходов каждого экрана — в [brief.md](brief.md), раздел 2.

Технически: `catalog`, `orders`, `profile` — «корневые» вкладки (`ROOT_TABS` в `router.js`), при переходе на них стек навигации сбрасывается, как в нативных приложениях с нижним таббаром. Остальные экраны — «стековые», открываются поверх текущего с кнопкой «Назад».

После успешной оплаты стек специально схлопывается до `Мои заказы → Статус заказа` (`Router.resetStackTo` в `router.js`, вызывается из `PaymentScreen` в `screens.js`) — иначе «Назад» вёл бы обратно в форму брифа уже оплаченного заказа.

## Где менять данные

Всё — в `tg-app/js/data.js`:
- **Название и описание сервиса**: объект `BRAND` (используется на экране приветствия, в шапке браузера, в разделе «О сервисе»)
- **Категории**: массив `CATEGORIES`
- **Услуги, цены, сроки, описания**: массив `SERVICES` (сейчас 13 услуг по вашему списку — можно добавлять/удалять/редактировать записи)
- **Демо-заказы для «Мои заказы»**: `MOCK_ORDERS`

## Важный нюанс: `telegram-web-app.js` вне настоящего Telegram

Официальный SDK, если открыть страницу в обычном браузере (не из Telegram), не просто «не работает» — он создаёт JS-заглушку версии 6.0. Часть её методов (`CloudStorage`, `setHeaderColor`, `BackButton` на некоторых сборках) **бросает исключение** при вызове, а `MainButton`/`BackButton` могут «успешно» принимать вызовы, но ничего не рисовать на странице (в реальном Telegram эти кнопки рисует нативный хост вне WebView).

Поэтому в `telegram.js`:
- каждый вызов `tg.*` обёрнут в `safeCall()` (try/catch) — недоступный метод не роняет приложение;
- показ MainButton/BackButton гейтится через `isTelegramEnv()` (проверка реального `initData`), а не через «существует ли метод» — вне настоящего Telegram всегда рисуется свой fallback-элемент (`.fallback-main-button`, `.fallback-back-button`), иначе кнопки становятся невидимыми и приложение нельзя тестировать в браузере.

Это уже протестировано (Playwright, полный проход по всем экранам, светлая и тёмная тема) — ошибок в консоли нет.

## Ограничения текущей версии (сделано намеренно, см. brief.md раздел 3)

- Нет бэкенда: заказы хранятся в памяти вкладки (`AppState.orders`), при перезагрузке страницы новые заказы (кроме `MOCK_ORDERS`) исчезают.
- Оплата — **симуляция**: кнопка «Оплатить» на экране `payment` через 1.2 сек имитирует успех вместо реального `tg.openInvoice()`. Когда появится бэкенд, в `PaymentScreen` (`screens.js`) нужно заменить `setTimeout(...)` на реальный вызов `openInvoice(invoiceUrl, callback)` со ссылкой, полученной от бота через Bot API (`createInvoiceLink`, оплата — Telegram Stars, см. [research.md](research.md) раздел 4.3).
- Загрузка файла в брифе сохраняется только в памяти вкладки (имя файла), не отправляется никуда — нужен бэкенд-аплоад.
- Статус заказа не меняется автоматически — в проде это делает провайдер услуги через админку/бота, присылая сообщение пользователю на каждом шаге воронки.
- Задать бренд/поддержку: замените `BRAND.name`, `BRAND.tagline`, `BRAND.supportBotUsername` в `data.js` на реальные.

## Как посмотреть локально

Просто открыть `tg-app/index.html` в браузере (двойным кликом или через любой статический сервер). Экран приветствия, каталог, оформление заявки и оплата (демо) работают полностью без интернета и бэкенда — кроме самого SDK `telegram-web-app.js`, который грузится с `telegram.org` (если офлайн — приложение всё равно не падает, просто работает в fallback-режиме).

Чтобы протестировать по-настоящему в Telegram: разместите папку `tg-app/` на HTTPS-хостинге, укажите URL в BotFather (`/newapp` или `Bot Settings → Menu Button`) и откройте через кнопку меню бота на телефоне.
