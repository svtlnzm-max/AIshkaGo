# TESTING.md — руководство для тестировщика

Telegram Mini App «Нейро.Студия» (`tg-app/`): каталог ИИ-услуг, HTML/CSS/JS без фреймворков, без бэкенда, вся логика на клиенте. Контекст проекта и карта экранов — в [CLAUDE.project.md](CLAUDE.project.md) и [brief.md](brief.md), этот документ — только про запуск и проверку.

**Автотестов в репозитории нет.** Нет `package.json`, нет конфига Playwright/Jest/др., папки с тестами тоже нет. Весь QA — только вручную по чек-листу ниже. (В CLAUDE.project.md упомянут прогон Playwright по всем экранам — это был разовый ручной прогон агентом, а не воспроизводимый тест в репозитории.)

---

## 1. Как запустить

Точка входа — **`tg-app/index.html`**. Сборки, `npm install`, бэкенда — нет.

**Способ 1 — просто открыть файл:**
Двойной клик по `tg-app/index.html`, откроется в браузере по умолчанию.

**Способ 2 — локальный статический сервер** (нужен, если браузер блокирует что-то по `file://`; PowerShell):
```powershell
cd tg-app
python -m http.server 8080
# затем открыть http://localhost:8080
```

Оба способа полностью рабочие офлайн, кроме одного момента: `index.html` подключает `https://telegram.org/js/telegram-web-app.js` с CDN (`tg-app/index.html:16`). Если интернета нет — этот скрипт не загрузится, `window.Telegram` не создастся, но приложение всё равно не падает (в `telegram.js` весь код проверяет `tg` на `null` — см. раздел 3).

## 2. Как проверить в настоящем Telegram

Бот проекта — **@AIshkaGoBot** (`BRAND.botUsername` в `tg-app/js/data.js:12`). Открыть Mini App на телефоне: `t.me/AIshkaGoBot/AIshkaGoBot` (short name, заданный в BotFather — виден в истории коммитов оффера) или через кнопку меню бота в чате.

Для реального деплоя: залить `tg-app/` на HTTPS-хостинг и прописать URL в BotFather (`/newapp` или Bot Settings → Menu Button) — подробнее в CLAUDE.project.md. В проекте есть папка `tg-app/.vercel/` (проект `tg-app` привязан к Vercel) — похоже, деплой уже настроен туда; проверьте текущий URL у владельца проекта, если нужно тестировать боевой билд.

На реальном устройстве отдельно проверьте (per `brief.md`, раздел 4): поведение клавиатуры и `safe-area-inset` в форме брифа — на iOS и Android известны расхождения, автор явно просит тестировать это отдельно.

## 3. Важно понять перед тестированием в браузере (не баг!)

Вне настоящего Telegram `telegram-web-app.js` создаёт JS-заглушку SDK версии 6.0: часть методов (`CloudStorage`, `setHeaderColor`, иногда `BackButton`) при вызове **бросает исключение**, а `MainButton`/`BackButton` может «успешно» отработать, но ничего не нарисовать на странице.

Поэтому в браузере (не в Telegram) вы **не увидите нативных** MainButton/BackButton — вместо них рисуются свои элементы:
- `.fallback-main-button` — кнопка снизу экрана (id `#fallback-main-button`);
- `.fallback-back-button` — кнопка «‹» сверху слева (id `#fallback-back-button`).

Это ожидаемое поведение (см. `tg-app/js/telegram.js:1-15`, функции `showMainButton`/`showBackButton`), **не считайте отсутствие нативной кнопки багом**. Баг — это если ни нативная, ни `.fallback-*` кнопка не появилась там, где она должна быть по чек-листу ниже.

Дополнительно: когда показан `.fallback-main-button`, таббар снизу скрывается (`body.has-fallback-main-button #tabbar { display: none; }`, `tg-app/css/style.css:178`) — тоже ожидаемо, а не пропажа навигации.

## 4. Сброс состояния между прогонами

Часть экранов показывается только один раз и помнит это через хранилище браузера (вне Telegram — `localStorage`, внутри Telegram — `CloudStorage`, см. `saveDraft`/`loadDraft` в `telegram.js:102-121`). Чтобы повторно увидеть эти экраны в браузере, в DevTools → Application → Local Storage удалите (или `localStorage.clear()` в консоли) ключи:

| Ключ | За что отвечает | Где в коде |
|---|---|---|
| `welcome_seen` | Показ экрана приветствия при первом входе | `app.js:25`, `screens.js:96` (`WelcomeScreen.onEnter`) |
| `offer_seen` | Показ модалки-оффера «Скидка 15%» при первом входе | `offer.js:8-18` |
| `draft_brief` | Черновик формы брифа (описание, срочность и т.п.) | `screens.js:294,304`, `screens.js:362` (очищается после оплаты) |

Заказы, оформленные в сессии (`AppState.orders`), хранятся только в памяти вкладки и обнуляются сами при перезагрузке страницы (`app.js:9-12`) — это штатное поведение MVP без бэкенда, а не баг.

## 7. Найденные при изучении кода несостыковки — стоит перепроверить и, вероятно, поправить

Это не подтверждённые баги «на глаз», а конкретные места в коде, которые стоит целенаправленно протестировать:

1. **Счётчик «13 ИИ-услуг» не совпадает с реальным количеством.**
   В `data.js` массив `SERVICES` содержит **14** записей (6 фото + 2 дизайн + 4 текст + 2 боты), но текст «Загляните в каталог — там 13 ИИ-услуг» зашит строкой в `screens.js:439` (пустое состояние «Мои заказы»), и то же число «13» упоминается в CLAUDE.project.md. Поскольку это пустое состояние сейчас недостижимо в UI (см. пункт 5.9), несовпадение никто не видел на экране. Стоит либо поправить текст на актуальное число, либо считать его динамически (`SERVICES.length`), чтобы не разъезжалось при следующем изменении каталога.

2. **`openSupportChat()` в `app.js:126-134` вызывает Telegram SDK в обход общего защитного механизма.**
   Весь проект намеренно оборачивает любые обращения к `window.Telegram.WebApp` в `safeCall()` (см. заглавный комментарий `telegram.js:1-15` и функцию `openTelegramLink()` там же, `telegram.js:142-145`) — потому что вне настоящего Telegram SDK-заглушка может бросить исключение прямо при вызове метода. Кнопка «Написать в поддержку» (экран статуса заказа и пункт «Поддержка» в профиле) это правило не соблюдает: она напрямую вызывает `window.Telegram.WebApp.openTelegramLink(...)` без `safeCall` и без использования уже существующего безопасного хелпера `openTelegramLink()` из `telegram.js`. Нужно целенаправленно проверить, не роняет ли эта кнопка приложение (ошибка в консоли, побитая навигация) в браузере и на старых клиентах Telegram — и если да, переиспользовать безопасный хелпер вместо прямого вызова.

3. **`supportBotUsername: '@neurostudio_support'` в `data.js:13` — плейсхолдер**, помечен `// TODO: заменить на реальный юзернейм бота поддержки` в самом коде. Кнопки «Написать в поддержку» будут вести на несуществующий юзернейм, пока его не заменят на реальный.

## 8. Куда смотреть, чтобы исправить найденное

| Симптом | Файл |
|---|---|
| Неверный текст/цена/описание услуги, категории или бренда | `tg-app/js/data.js` |

| Не показывается/не закрывается модалка-оффер | `tg-app/js/offer.js` |
| Проблемы со стилями, цветом, тёмной темой, версткой | `tg-app/css/style.css` |
