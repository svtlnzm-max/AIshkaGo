# Бриф: пошаговый план разработки Telegram Mini App «ИИ-услуги»

Составлено на основе [research.md](research.md). Это рабочий план для разработки MVP — каталог ИИ-услуг с формой-брифом, оплатой через Telegram Stars и статусом заказа. Заказы выполняются вручную/полуавтоматически провайдером услуг (ИИ-инструменты + человек), а не автогенератором внутри приложения — поэтому в MVP нет пайплайна генерации, только каталог → бриф → оплата → статус → результат в чате.

---

## 0. Принципы дизайна (действуют на всех экранах)

- **Нативный вид Telegram:** только системные цвета через `ThemeParams` (`var(--tg-theme-*)`), поддержка светлой/тёмной темы «из коробки», без своей брендовой палитры поверх системной.
- **Крупные кнопки:** основное действие экрана — всегда `MainButton` (высота ≥48px, на всю ширину), второстепенное — `SecondaryButton` или обычная кнопка ≥44px.
- **Минимум текста:** заголовок + 1 короткая подпись на блок, остальное — иконки/фото/визуальные карточки. Никаких абзацев.
- **Русский язык** — весь интерфейс, кнопки, статусы, подсказки.
- **Ощущение приложения, а не сайта:**
  - Один `index.html`, дальше — client-side роутинг (SPA), без перезагрузки страницы между экранами.
  - Навигация через `BackButton` Telegram вместо браузерных «назад»/URL-бара.
  - `ready()` и `expand()` вызываются сразу при старте, интерфейс сразу на весь экран.
  - Переходы между экранами —슬айд/fade-анимация 150–200мс, без «мигания» белого фона при загрузке.
  - `HapticFeedback` на нажатия ключевых кнопок (выбор карточки, отправка формы, оплата).
  - Системные попапы (`showConfirm`, `showAlert`) вместо кастомных модалок — привычное поведение Telegram.

## 1. Карта экранов (обзор)

```
Приветствие (1 раз)
      │
      ▼
Каталог (Главная) ──▶ Категория ──▶ Карточка услуги ──▶ Бриф/Заявка ──▶ Оплата ──▶ Статус заказа ──▶ Результат
      │                                                                                  │
      ├──▶ Мои заказы (история) ◀───────────────────────────────────────────────────────┘
      │
      └──▶ Профиль/Поддержка
```

Нижняя навигация (Tab Bar, 3 вкладки): **Каталог** · **Мои заказы** · **Профиль**.

## 2. Экраны подробно

### 2.1 Экран приветствия (показывается один раз при первом входе)
**Назначение:** объяснить за 3 секунды, что за приложение, без текста-простыни.

**Элементы:**
- Крупная иллюстрация/эмодзи-визуал «до/после» (пример фото или карточки)
- Заголовок: «ИИ создаёт, вы получаете результат»
- Подпись (1 строка): «Фото, дизайн, тексты и боты — с помощью ИИ»
- Кнопка `MainButton`: «Начать»

**Действия:** нажатие «Начать»

**Переходы:** → Каталог (Главная)

**Примечание:** экран можно пропустить в MVP, если критично сократить объём работы — не обязателен для первой версии (см. раздел 4).

---

### 2.2 Каталог (Главная)
**Назначение:** точка входа, обзор всех категорий услуг.

**Элементы:**
- Верхний блок: короткое приветствие по имени из Telegram-профиля («Привет, Анна 👋»)
- Поисковая строка (иконка лупы + placeholder «Что нужно сделать?»)
- Сетка категорий — крупные плитки с иконкой/фото и названием:
  - 📸 Фото и изображения
  - 🎨 Дизайн
  - ✍️ Тексты и объявления
  - 🤖 ИИ-боты и консультации
- Блок «Популярное» — 3–4 карточки конкретных услуг с мини-превью «до/после», ценой и сроком
- Нижний Tab Bar: Каталог / Мои заказы / Профиль

**Действия:** тап по категории, тап по карточке услуги, тап по строке поиска

**Переходы:**
- Категория → Экран категории
- Карточка услуги → Карточка услуги
- Поиск → список результатов (тот же вид, что экран категории)

---

### 2.3 Экран категории (список услуг)
**Назначение:** выбор конкретной услуги внутри категории.

**Элементы:**
- Заголовок категории (например «Фото и изображения»)
- Список карточек услуг, для каждой:
  - Миниатюра «до/после» или пример результата
  - Название услуги (1 строка)
  - Цена от … ₽ и срок («от 500 ₽ · 1 день»)
- `BackButton` в шапке

**Действия:** тап по карточке услуги, `BackButton`

**Переходы:**
- Карточка → Карточка услуги
- `BackButton` → Каталог (Главная)

---

### 2.4 Карточка услуги
**Назначение:** убедить и подвести к заказу — ключевой конверсионный экран.

**Элементы:**
- Галерея примеров «до/после» (свайп, 3–5 фото)
- Название услуги
- Цена и срок выполнения крупным шрифтом
- Короткое описание (2–3 строки максимум, без «простыни»)
- Список «что входит» — 3–4 пункта с иконками-галочками
- `MainButton`: «Заказать за … ₽»

**Действия:** свайп галереи, тап «Заказать»

**Переходы:** «Заказать» → Экран брифа/заявки

---

### 2.5 Экран брифа / заявки
**Назначение:** собрать всё нужное для выполнения заказа в одной форме — заменяет классическую «корзину».

**Элементы (состав зависит от типа услуги, общий шаблон):**
- Загрузка фото/файла (крупная зона с иконкой камеры/скрепки — «Прикрепить фото»)
- Текстовое поле «Опишите, что нужно» (placeholder с примером, не пустое поле)
- Быстрый выбор опций чипами, если применимо (например стиль: «Деловой / Творческий / Праздничный»)
- Поле «Когда нужно» — быстрый выбор: «Сегодня / Завтра / Не срочно»
- Сводка внизу: итоговая цена
- `MainButton`: «Перейти к оплате»

**Действия:** прикрепить файл, ввести текст, выбрать чип, тап «Перейти к оплате», `BackButton`

**Переходы:**
- «Перейти к оплате» → Экран оплаты
- `BackButton` → Карточка услуги (черновик сохраняется в CloudStorage, не теряется)

---

### 2.6 Экран оплаты
**Назначение:** финальное подтверждение и оплата — без выхода из Telegram.

**Элементы:**
- Краткая сводка заказа: услуга, ключевые параметры из брифа, срок
- Итоговая цена
- `MainButton`: «Оплатить … ⭐» (Telegram Stars через `openInvoice()`)
- Мелкая подпись: «Оплата через Telegram, безопасно»

**Действия:** тап «Оплатить», `BackButton`

**Переходы:**
- Успешная оплата → Экран статуса заказа
- `BackButton` → Экран брифа (редактирование)

---

### 2.7 Экран статуса заказа
**Назначение:** снять тревогу ожидания, показать прогресс.

**Элементы:**
- Прогресс-индикатор из 4 шагов: **Принято → В работе → На проверке → Готово**, текущий шаг подсвечен
- Иконка/анимация текущего этапа
- Короткий текст: «Обычно занимает … Мы напишем, когда будет готово»
- Кнопка (вторичная): «Написать в поддержку»

**Действия:** тап «Написать в поддержку»

**Переходы:**
- «Написать в поддержку» → чат с ботом/оператором (внутри Telegram, не Mini App)
- Автоматически при готовности заказа → бот присылает сообщение со ссылкой → Экран результата

---

### 2.8 Экран результата
**Назначение:** показать готовую работу, закрыть сделку эмоционально, подтолкнуть к повторному заказу.

**Элементы:**
- Крупное превью результата (фото/файл), формат «до/после» если применимо
- `MainButton`: «Скачать»
- Вторичная кнопка: «Поделиться»
- Вторичная кнопка: «Заказать ещё»

**Действия:** скачать, поделиться (шаринг в чат через `shareMessage()`), заказать ещё

**Переходы:**
- «Скачать» → сохранение файла
- «Поделиться» → нативное меню шаринга Telegram
- «Заказать ещё» → Каталог (Главная)

---

### 2.9 Мои заказы (история, вкладка Tab Bar)
**Назначение:** быстрый доступ к прошлым и текущим заказам.

**Элементы:**
- Список карточек заказов: миниатюра, название услуги, статус (цветной бейдж), дата
- Пустое состояние (если заказов нет): иллюстрация + «Пока нет заказов» + `MainButton` «Перейти в каталог»

**Действия:** тап по заказу

**Переходы:** тап по заказу → Экран статуса заказа (или Экран результата, если готов)

---

### 2.10 Профиль (вкладка Tab Bar)
**Назначение:** личные данные, поддержка, базовые настройки.

**Элементы:**
- Фото и имя из Telegram-профиля (автоматически, без формы регистрации)
- Пункт «Мои заказы» (дублирует вкладку)
- Пункт «Поддержка»
- Пункт «О сервисе»

**Действия:** тап по пункту меню

**Переходы:**
- «Поддержка» → чат с ботом
- «О сервисе» → короткий экран с описанием (1 экран, минимум текста)

## 3. Чего НЕ будет в первой версии (MVP)

Сознательно вынесено за скобки, чтобы не раздувать первую версию:

- ❌ Автоматическая ИИ-генерация внутри приложения (заказ выполняется провайдером вручную/полуавтоматически, результат приходит через бот)
- ❌ Выбор мастера/исполнителя — в v1 один провайдер услуг, не маркетплейс
- ❌ Публичные отзывы и рейтинги (заменяются примерами «до/после» в карточках)
- ❌ Абонементы, пакеты услуг, скидки за объём
- ❌ Реферальная программа
- ❌ CRM-аналитика и сегментация клиентов (только базовая история заказов)
- ❌ Мультиязычность (только русский)
- ❌ Push-напоминания по расписанию (только событийные сообщения бота: оплата, готовность заказа)
- ❌ Онбординг с несколькими экранами — максимум один экран приветствия, и тот опционален
- ❌ Расширенный поиск с фильтрами по цене/сроку (в v1 — простой текстовый поиск)
- ❌ Интеграция с внешними CRM/платёжными системами, кроме Telegram Stars

## 4. Технические заметки «это приложение, не сайт»

- SPA на клиентском роутинге (без перезагрузки страницы), состояние экрана хранится в памяти + черновик заявки дублируется в `CloudStorage`, чтобы не терять данные при случайном сворачивании.
- Все переходы — через `BackButton` и внутренний stack навигации, а не через URL/адресную строку.
- `openLink()` для внешних ссылок не используется нигде, кроме крайних случаев (например ссылка на «О сервисе», если это внешний лендинг).
- Оплата — только `openInvoice()` с Telegram Stars (см. [research.md](research.md), раздел 4.3): встроить в архитектуру сразу, не как «доработку потом».
- Тестировать форму брифа (поле ввода + загрузка файла) отдельно на iOS и Android — известны расхождения в поведении клавиатуры и `safe-area-inset`.
- `isVersionAtLeast()` перед использованием новых WebApp-функций (Tab Bar через нативные средства может быть недоступен на старых клиентах — тогда верстать нижнюю навигацию вручную, но визуально идентично нативной).
