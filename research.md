# Исследование: Telegram Mini App для ИИ-услуг

Ниша проекта: консультации по ИИ-продуктам, создание AI-изображений, AI-фотосессии, обработка и улучшение фотографий, восстановление и раскрашивание старых фото, видео из фото, дизайн и оформление презентаций, оформление карточек товаров, написание и оформление объявлений для Авито, написание текстов, создание контента для соцсетей, создание промптов, разработка ИИ-помощников и чат-ботов — всё в формате Telegram Mini App (каталог услуг + запись/заказ + оплата).

---

## 1. Примеры конкурентов и аналогов

### 1.1 Slotly — запись в барбершопы/салоны красоты (каталог + CRM)
**Что делает:** Mini App для онлайн-записи (барбершопы, маникюр, автосервис) внутри Telegram/MAX без отдельного приложения.

**Сильные стороны:** один экран «мастер → услуга → слот → цена»; встроенная CRM (история визитов, заметки, предпочтения клиента); абонементы и авто-напоминания против неявок; бесплатный вход без привязки карты.

**Слабые стороны:** слабая визуальная витрина — нет портфолио/фото работ в карточке; оплата и запись разнесены, явного Telegram Payments нет; не видно работы с отзывами/рейтингами.

**Что сделать лучше:** взять логику «услуга → мастер → слот → цена → подтверждение» для записи на консультацию/AI-фотосессию + добавить портфолио «до/после» прямо в карточке услуги, чего у Slotly нет.

### 1.2 AI Photo Forge — AI-портреты и аватары в Telegram
**Что делает:** превращает 1–12 селфи в профессиональные портреты/аватары в 30+ стилях за 2–3 минуты.

**Сильные стороны:** простой флоу «загрузка → стиль → результат»; бесплатная пробная генерация снижает страх покупки; удаление данных через 30 дней (забота о приватности лиц); готовые стили вместо промпт-инжиниринга.

**Слабые стороны (по структуре сервиса):** типично для класса — непрозрачные кредиты/тарифы до оплаты, нет предпросмотра перед списанием, отсутствие прогресс-бара ожидания.

**Что сделать лучше:** показывать демо-генерацию до оплаты, прозрачную цену пакета кредитов и понятный индикатор прогресса генерации.

### 1.3 «+Вайб Бот» — каталог AI-фотосессий, видео, аватаров (Mini App)
**Что делает:** 3500+ готовых шаблонов и 30 000+ примеров, генерация фото/видео/говорящих аватаров, редактирование (удаление фона/объектов) — всё в одном Mini App.

**Сильные стороны:** превью результата на чужом примере снижает неопределённость до покупки; freemium (первая генерация бесплатно → пакеты); все AI-услуги в одном интерфейсе без переключения ботов.

**Слабые стороны:** непрозрачное ценообразование пакетов; большой каталог шаблонов без явных фильтров — «стена карточек».

**Что сделать лучше:** превью «до/после» именно под ваш формат услуги (не общий пример), цена и срок сразу на карточке, категории-фильтры (Фото · Дизайн · Тексты · Боты) вместо бесконечной ленты.

### 1.4 «Эхо времени» — реставрация старых фото (бот, не Mini App, но эталон UX-паттерна)
**Что делает:** восстанавливает старые/повреждённые чёрно-белые фото через Replicate API с защитой идентичности лица.

**Сильные стороны:** трёхшаговый сценарий «загрузил → статус "Восстанавливаю..." → результат до/после»; понятный freemium (бесплатно база, платно HD/без водяного знака/приоритет); очередь обработки; эмоциональная подача формирует виральность.

**Слабые стороны:** полная зависимость от внешнего API; были проблемы с искажением лиц; нет предпросмотра перед оплатой HD — платишь вслепую.

**Что сделать лучше:** обязательный статус-индикатор процесса (особенно критично для долгих задач — фотосессии, видео из фото); формат «до/после» как стандарт карточки результата; бесплатное превью в низком качестве перед оплатой апгрейда.

### 1.5 Telegram Mini App «Цветов.ру» — маркетплейс (для сравнения архитектуры каталога)
**Что делает:** цветочный маркетплейс (45 своих + 382 партнёрских магазина), Flutter-приложение адаптировано под Mini App за месяц: каталог с фильтрами, карточки с галереями и отзывами, профиль, трекинг заказа, чат с магазином, несколько способов оплаты.

**Сильные стороны:** авторизация через Telegram без отдельной регистрации; дешёвое продвижение через Telegram Ads; быстрый запуск на готовой кодовой базе; 102 млн руб. оборота за первый год.

**Слабые стороны:** нет открытых метрик retention/конверсии по самому Mini App; оплата «наличные»/«карта в магазине» — по сути обход нативных Telegram Payments, что усложняет автоматизацию.

**Что сделать лучше:** для ИИ-услуг вместо простой корзины — форма-бриф под каждую услугу (загрузка исходного фото/текста, требования, дедлайн); статусы заказа как воронка «принято → в работе → на согласовании → готово»; оплата строго через `openInvoice`/Telegram Payments/Stars, а не наличные; раздел «повторить заказ в один клик» (актуально для регулярных карточек Авито).

**Общий вывод по рынку:** ни один найденный пример не совмещает полностью каталог с наглядным «до/после» + прозрачную цену на карточке + бриф/запись + встроенную оплату + статус выполнения. Это свободная ниша для нашего продукта.

## 2. Типовые экраны каталога услуг / записи / витрины

1. Главная/каталог — категории, поиск, баннеры
2. Карточка услуги — описание, цена, примеры «до/после», отзывы, кнопка заказа
3. Корзина / форма-бриф (для услуг часто заменяет корзину: бронирование слота или заявка с требованиями)
4. Оформление заказа — дата/время, исполнитель, способ оплаты
5. Профиль — данные, настройки, реферальная программа
6. История заказов / кабинет — статусы, повтор заказа
7. Отзывы и рейтинги
8. Поддержка/чат
9. Экран оплаты и подтверждения статуса

## 3. Обязательные UI-элементы Telegram Mini App

- **MainButton/SecondaryButton** — нижняя кнопка основного действия, с состояниями loading/disabled
- **BackButton** — навигация вместо кастомных стрелок
- **ThemeParams** — адаптация под системную тему Telegram через `var(--tg-theme-*)`, без своей палитры
- **HapticFeedback** — тактильный отклик на ключевые действия
- **initData + HMAC-SHA256** — авторизация без логина/пароля
- **openInvoice() / Telegram Payments / Stars** — оплата внутри приложения, без внешних страниц
- **shareMessage()/switchInlineQuery()** — шаринг карточки в чат
- **showPopup/showAlert/showConfirm** — системные диалоги вместо кастомных модалок
- **CloudStorage** — сохранение черновиков заявок/настроек
- **safeAreaInset/requestFullscreen** — корректная работа с полноэкранным режимом
- Общие принципы: mobile-first, действие не должно требовать выхода из Mini App

## 4. Экспертная оценка

### 4.1 Взгляд UX-дизайнера

**Типичные ошибки новичков в Mini App для услуг/каталогов:**
- Копируют паттерны обычного интернет-магазина (корзина с товарами) вместо брифа под услугу — для AI-генерации и дизайна нужен не «товар», а «заявка с требованиями и исходными файлами».
- Прячут цену и срок выполнения за дополнительный клик или «узнать после загрузки» — пользователь уходит, не дойдя до оплаты.
- Не показывают статус долгой обработки (генерация фото/видео может идти минуты) — тишина после отправки заявки читается как «зависло», пользователь закрывает приложение.
- Собственная цветовая палитра и кастомные модалки вместо `ThemeParams` и `showPopup/showConfirm` — приложение выглядит чужеродным внутри Telegram и не адаптируется под тёмную тему.
- Каталог из 12+ разнородных услуг без категорий и фильтров превращается в «стену карточек», где сложно найти нужное.
- Нет примеров результата («было/стало») в карточке услуги — для визуальных AI-услуг это решающий фактор доверия, а не опция.

**Что обязательно должно быть:**
- Категории/фильтры услуг (Фото · Дизайн · Тексты · Боты · Консультации) — не единый список.
- Цена и срок выполнения видны сразу на карточке услуги, без дополнительных кликов.
- Формат «до/после» — обязательный визуальный паттерн для фото/дизайн-услуг.
- Индикатор статуса выполнения (очередь → в работе → готово) для всего, что занимает больше нескольких секунд.
- Нативные MainButton/BackButton, системная тема, haptic feedback — приложение должно ощущаться «родным» для Telegram.
- Форма-бриф с загрузкой файла и текстовым полем требований — универсальный паттерн для творческих/AI-услуг.

**Что раздражает пользователей:** долгая загрузка без обратной связи; необходимость выходить из Telegram на внешний сайт для оплаты или просмотра результата; скрытая стоимость, которая всплывает только на последнем шаге; отсутствие возможности посмотреть примеры прошлых работ перед заказом; слишком длинные формы вместо пошагового флоу.

### 4.2 Взгляд маркетолога

**Что заставит записаться:**
- Бесплатная или очень дешёвая пробная генерация/демо (снижает страх «купить кота в мешке» — этот паттерн работает у всех успешных AI-ботов в нише).
- Наглядная галерея «было/стало» прямо в каталоге, а не только в отдельной карточке — решение о заказе принимается визуально, до чтения текста.
- Прозрачная цена и срок на каждой карточке услуги — скрытая цена = отказ на этапе просмотра каталога.
- Социальное доказательство: отзывы, счётчик выполненных заказов/генераций, рейтинг исполнителя.
- Ограниченные по времени предложения и пакеты (например «3 карточки товара со скидкой» или «пакет из 10 AI-фото дешевле поштучной цены») — повышают средний чек.
- Реферальная программа/шаринг результата в чат — карточка с результатом «до/после» сама по себе виральна, стоит встроить кнопку «поделиться».
- Push-подобные уведомления о статусе заказа (через сообщения бота) — возвращают пользователя в диалог без давления.

**Элементы, повышающие конверсию:**
- Минимум шагов от каталога до оплаты (в идеале 3: выбрал услугу → заполнил бриф → оплатил).
- Оплата без выхода из Telegram (Stars/Telegram Payments) — каждый лишний переход на внешний сайт теряет часть пользователей.
- Прогресс-бар/шаги оформления заказа — снижает тревогу «сколько ещё осталось».
- «Повторить заказ в один клик» для регулярных услуг (карточки товаров, объявления Авито, контент для соцсетей) — увеличивает LTV.
- Персонализация каталога под историю заказов (CRM-профиль клиента, как у Slotly).

### 4.3 Взгляд Telegram-разработчика

**Ключевое ограничение — обязательность Telegram Stars.** С июня 2024 года оплата **цифровых** товаров и услуг внутри ботов и Mini App должна идти **только через Telegram Stars** — сторонние эквайринги (ЮKassa, Stripe и т.п.) для этого запрещены политикой Telegram, при нарушении приложение может быть скрыто от мобильных пользователей. Все услуги проекта (AI-фото, дизайн, тексты, промпты, боты) — это цифровые услуги, значит оплата должна идти через Stars или `openInvoice()` с нативным Telegram Payments. Исключение — только физические товары/услуги, но их в этом проекте нет.

**Технические ограничения:**
- CloudStorage: до 1024 ключей на пользователя, до 4096 символов на значение — достаточно для черновиков брифа, но не для хранения самих файлов.
- DeviceStorage: до 5 МБ на пользователя.
- Персистентность состояния при закрытии/сворачивании Mini App **не гарантируется нативно** — состояние брифа/заявки нужно сохранять на бэкенде или в CloudStorage самостоятельно, иначе пользователь потеряет заполненную форму при случайном закрытии.
- Push-уведомлений вне сообщений бота не существует — любое «уведомление о готовности заказа» технически реализуется как сообщение от бота, это нужно закладывать в сценарий, а не ждать отдельного API.
- `sendData()` — одноразовая отправка, после которой Mini App обычно закрывается; не подходит для многошаговых сценариев без отдельного бэкенда.

**Что работает хорошо:**
- Ранний вызов `ready()`, нативные MainButton/BackButton, уважение к `ThemeParams`.
- Обязательная валидация `initData` через HMAC-SHA-256 на сервере — без своего логина/пароля, но безопасно.
- `isVersionAtLeast()` для проверки доступности фич перед использованием (клиенты Telegram обновляются не одновременно).

**Что лучше не делать:**
- Не открывать внешние ссылки (`openLink()`) без явного жеста пользователя и без крайней необходимости — уводит из Telegram и снижает конверсию.
- Не рассчитывать на недокументированную персистентность данных между сессиями.
- Не заводить кастомные диалоги/попапы вместо `showPopup/showAlert/showConfirm` — ломает нативность и предсказуемость UX.
- Учитывать известные баги WebView: клавиатура перекрывает поля ввода на iOS, проблемы с `safe-area-inset` снизу на iOS, разное поведение полноэкранного режима на iOS/Android — тестировать формы брифа отдельно на обеих платформах.
- Не откладывать интеграцию Stars «на потом» — если оплата изначально спроектирована под внешний эквайринг, переделка архитектуры платежей задним числом дорога.

## 5. Общий список рекомендаций (сводка)

1. **Каталог с категориями** (Фото · Дизайн · Тексты · Боты · Консультации), а не единый список из 12+ услуг.
2. **Цена и срок выполнения — сразу на карточке услуги**, без скрытых доплат на последнем шаге.
3. **Формат «до/после» как обязательный элемент** карточки для всех визуальных услуг (фото, дизайн, карточки товаров).
4. **Форма-бриф вместо классической корзины**: загрузка исходного файла/фото + текстовое поле требований + дедлайн.
5. **Статус выполнения заказа как воронка**: принято → в работе → на согласовании → готово, с уведомлением через сообщение бота на каждом шаге.
6. **Бесплатная или дешёвая демо-генерация** перед платной услугой — снижает порог входа.
7. **Оплата только через Telegram Stars / `openInvoice()`** — это не опция, а требование политики Telegram для цифровых услуг; закладывать в архитектуру с самого начала.
8. **Сохранение состояния брифа/заявки на бэкенде или в CloudStorage** — Mini App не гарантирует персистентность при случайном закрытии.
9. **Нативные UI-компоненты Telegram** (MainButton, BackButton, ThemeParams, HapticFeedback, системные попапы) вместо кастомных — для ощущения «родного» приложения.
10. **CRM-профиль клиента**: история заказов, предпочтения, повтор заказа в один клик — особенно ценно для регулярных услуг (карточки товаров, объявления Авито, контент для соцсетей).
11. **Отзывы, рейтинг, счётчик выполненных заказов** — социальное доказательство прямо в каталоге.
12. **Кнопка «поделиться результатом»** — карточки «до/после» виральны, стоит закладывать шаринг в чат как канал привлечения.
13. **Тестировать формы и полноэкранный режим отдельно на iOS и Android** — известны расхождения в поведении клавиатуры и safe area.
